# 内功修炼

相关笔记：[[第一性原理]]、[[多元思维工具训练]]、[[思考]]

> [!summary] 核心目的
> 让自己能从真实经历中持续发现差距、改进方法、提高标准，并把少量可靠经验沉淀成可复用的方法和工作模型。

“螺旋上升最小闭环”是这套内功的训练机制，不是最终目的。

```text
真实目标
→ 测量现状
→ 改变一个变量
→ 获取结果
→ 保留有效方法
→ 提高标准
→ 在新问题中继续验证
```

## 为什么叫“内功”

它不绑定某个职业、学科或工具。训练的是底层能力：

```text
把愿望变成可测试目标
看见自己与目标的真实差距
用证据筛选方法
发现当前最大瓶颈
在失败后调整而不是重启
把零散经验压缩成少量规律
逐步提高处理问题的难度
```

## 最小训练闭环

> [!abstract] 螺旋上升最小闭环
> 对同一个可测目标反复尝试；每轮根据证据只调整一个主要变量；有效做法留下，无效做法删除；稳定后提高标准。

```text
明确结果
→ 测量基线
→ 找最大差距
→ 只改一个变量
→ 事前预测
→ 实际执行
→ 比较结果
→ 保留或删除
→ 再做一轮
→ 提高标准
```

## 为什么是“螺旋”，不是普通循环

普通循环只是在重复：

```text
做 → 失败 → 再做同样的事
```

螺旋上升每轮至少留下一个变化：

```text
更准确的事实
更有效的方法
更明确的边界
更高的验收标准
```

不需要每天换目标。一个目标通常连续运行 7 到 14 天，或者运行到证据足够为止。

## 每轮只回答六个问题

```text
1. 我想改善哪个可测结果？
2. 目前真实结果是多少？
3. 当前最大的一个差距是什么？
4. 本轮只改变什么？
5. 我预计改变后会发生什么？
6. 实际结果支持保留、修改还是删除？
```

## 从现成模型开始：一次只练一个

完整工具地图和五个训练单元见：[[多元思维工具训练]]。

不用等自己从生活中发明模型。刚开始时，主要路线应该是：

> **学习人类已经总结出的模型，一次只练一个，再用自己的案例、预测和行动把它变成自己的。**

芒格式多元模型不是背诵一张名词表，而是逐步建立一组来自不同学科、能共同检查问题的思维工具。

模型有两种进入方式：

```text
主路线：学习现成模型
理解机制 → 找案例 → 找反例 → 事前预测 → 现实验证 → 指导行动

辅助路线：从个人实践提出候选模型
多次结果 → 候选解释 → 跨场景预测 → 现实验证 → 暂时保留
```

### 先分清来源

| 内容                   | 来源                            |
| -------------------- | ----------------------------- |
| 建立跨学科的多元思维模型网        | 芒格反复强调的核心框架                   |
| 能力圈、逆向思考、激励检查、认知偏误检查 | 芒格重点使用和传播的工具                  |
| 激励、机会成本、概率、反馈循环等具体模型 | 来自经济学、心理学、数学、系统科学等学科，并非芒格个人发明 |
| “一次只练一个模型”           | 本文为了避免浅尝辄止设定的训练原则             |
| 下面的六步训练流程            | 本文设计的实践方法，不是芒格原话或官方课程         |

所以答案是：

> **你可以沿着芒格倡导的多元模型路线学习，但不能把本文设计的训练流程冒充成芒格的方法。**

### 一个模型怎样才算练过

不规定必须七天。完成下面六步才算一轮；可能需要三天，也可能需要三周。

```text
1. 搞懂：能不用术语讲清模型和机制。
2. 应用：能解释一个外部案例和一个自己的案例。
3. 反驳：能找到反例和失效边界。
4. 预测：在结果发生前写下可失败的预测。
5. 验证：观察结果，或按模型采取一次行动。
6. 沉淀：根据结果保留、修改或删除模型卡。
```

一次只练一个模型。当前模型完成这六步后，再开始下一个。

### 完整案例：激励机制

> [!note] 来源说明
> “重视激励”是芒格反复强调的分析习惯，但激励机制属于经济学与心理学的基础模型，不是芒格个人发明。

#### 第 1 步：搞懂

```text
一句话：行为通常会向实际获得奖励、避免惩罚的方向移动，而不是向口号移动。

机制链：
某种行为
→ 获得金钱、关注、轻松、地位或避免惩罚
→ 这种行为出现得更频繁
→ 长期形成稳定结果
```

#### 第 2 步：应用案例

假设一个团队口头要求“解决重要问题”，但绩效只统计关闭任务的数量。

```text
被奖励：关闭更多任务。
最容易增加数量的行为：优先完成简单任务。
预测结果：简单任务快速关闭，复杂任务持续积压。
```

这里分析的是假设场景，不是对某个真实团队的事实判断。

自己的案例：

```text
嘴上目标：长期学习有价值的知识。
即时奖励：随机内容马上提供新鲜感和轻松感。
延迟奖励：系统学习需要较长时间才看到收益。
实际行为：更容易打开随机内容。
```

模型指出：问题不只在“自控力”，还在两种行为的奖励速度完全不同。

#### 第 3 步：反例和边界

```text
反例：有人在没有金钱奖励时，仍然长期照顾家人或研究问题。

边界：
激励强烈影响行为，但不是唯一原因。
身份认同、道德、使命感、感情和强制规则也会改变行为。
```

#### 第 4 步：事前预测

```text
场景：团队继续只按关闭任务数量评价表现。
预测：下周成员仍会优先选择更容易关闭的任务。
失败标准：复杂任务被稳定优先处理，而且没有额外奖励或强制要求。
```

#### 第 5 步：验证与行动

模型建议先改变实际奖励，而不是继续喊口号。

```text
候选行动：评价中加入复杂问题解决质量、返工率或长期效果。
观察：行为是否从“追求数量”转向“解决重要问题”。
```

真实使用时，指标必须根据具体团队设计，不能照抄这个假设案例。

#### 第 6 步：模型卡

```markdown
# 模型：激励机制

- 一句话：行为会适应实际奖惩，而不是自动服从口头目标。
- 触发问题：谁因为什么行为获得什么？谁承担代价？
- 机制：奖励提高行为频率，惩罚降低行为频率。
- 它能预测：奖励结构不变，只喊口号，行为通常不会稳定改变。
- 它指导的行动：想改变行为，先检查实际奖励结构。
- 边界：使命感、身份、道德和强约束也可能压过短期奖励。
- 状态：继续用真实案例验证。
```

### 起步模型顺序

当前模型完成“搞懂、应用、反驳、预测、验证、沉淀”六步后，再进入下一个。不要按日历强行赶进度。

1. 激励机制
2. 机会成本
3. 逆向思考
4. 概率与基准率
5. 瓶颈
6. 反馈循环与延迟
7. 复利
8. 安全边际

这些模型不全由芒格发明。芒格的关键贡献是要求从多个基础学科中取出重要模型，织成相互校验的网。

## 怎样从实践沉淀方法和候选模型

每次循环一定产生证据，不一定产生方法，更不一定产生模型。这是正常情况。

```text
一次结果
→ 只是记录

同一做法在同类任务中反复有效
→ 个人方法

同一解释跨不同场景成立，并提前预测成功
→ 工作模型
```

正确积累方向：

```text
大量事实
→ 少量方法
→ 极少模型
```

### 方法晋级条件

- [ ] 在同一类任务中实际使用至少三次
- [ ] 多数结果优于基线
- [ ] 做法足够具体，可以直接照做
- [ ] 知道至少一个失效情况

## 完整案例：改善准时到达

### 目标和基线

```text
目标：工作日8:55前到达。
基线：最近五天只有两天达标。
```

三次基线记录：

| 次数 | 做法 | 结果 | 可观察事实 |
| ---: | --- | --- | --- |
| 1 | 凭感觉出门 | 9:07 | 8:24离家，路程43分钟 |
| 2 | 凭感觉出门 | 8:58 | 8:17离家，路程41分钟 |
| 3 | 提前起床 | 9:12 | 起床提前，但8:29才离家 |

当前最大差距：离家时间不稳定。

### 第一轮

```text
只改变：提前十分钟起床。
预测：到达时间平均提前十分钟。
结果：仍然迟到。
证据：起床提前，但离家时间没有稳定提前。
结论：删除“只提前起床”这个做法。
```

### 第二轮

```text
只改变：固定8:10离开家。
预测：路程即使波动，也能在8:55前到达。
结果：8:48、8:52、8:50、8:54、8:49。
结论：保留。
```

### 沉淀成方法

```markdown
# 方法：固定离家时间

- 解决的问题：到达时间不稳定
- 触发场景：工作日通勤
- 具体步骤：8:05收尾，8:10离家
- 成功指标：8:55前到达
- 有效证据：连续五次达标
- 失效情况：重大交通异常
```

### 候选模型仍需验证

从这个方法可以提出候选解释：

```text
控制最接近结果的关键动作，通常比控制更远、更模糊的愿望稳定。
```

一个通勤案例不够。先做新预测：

```text
如果这个解释成立，固定“晚上9点坐下并翻开书”，
应该比“今晚要学习”更能提高开始次数。
```

只有事前写下预测，并在新场景实际验证成功，才考虑把它晋级为模型。

## 与第一性原理怎样配合

当你认为“只能这样做”，先用 [[第一性原理]] 重新设计：

```text
真正目标是什么？
哪些信息有证据？
哪些条件必须保留？
当前方案依赖什么假设？
还有哪些变量可以改变？
```

得到新方案后，进入本笔记的闭环：

```text
测基线
→ 只改一个变量
→ 写事前预测
→ 执行
→ 比较结果
→ 保留、修改或删除
```

## 最小执行规则

1. 同时只运行一个主要内功项目。
2. 每轮只改变一个主要变量。
3. 先写预测，再看结果，防止事后编故事。
4. 没有证据就写“不知道”。
5. 一次成功不沉淀方法，单一场景不沉淀模型。
6. 达到当前标准后，提高难度或扩大使用场景。
7. 方法和模型的价值在于改变下一步行动，不在于数量。
